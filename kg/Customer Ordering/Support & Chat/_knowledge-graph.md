# Support & Chat — Knowledge Graph

> **Context:** Customer Ordering
> **Last Updated:** 2026-08-02

**Depth for the in-house chat system lives in `docs/CHAT_*.md`, deliberately.** The full technical detail —
entities (`ChatContext` SQL legacy, `ChatContextV2` Cassandra), message flow, bot mechanics,
reporting — already lives in `docs/CHAT_FEATURE_REFERENCE.md` (1,363 lines) and the other linked
`docs/CHAT_*.md` files, referenced from `_overview.md`. Duplicating that here would create two
sources of truth that could drift; if a future CR needs entity-level citations for chat, read
`CHAT_FEATURE_REFERENCE.md` directly rather than expecting them in this knowledge graph.

**TawkTo** and **Contact Us** are separate, much smaller surfaces. Both are now covered at endpoint
depth in the generated index below and behaviourally in
[[Customer Ordering/Support & Chat/_scenarios|the scenario catalog]], which also documents the split
this feature turns on: `GetAdminChatMessagesQuery.cs:113` enforces chat ownership on the read path,
while `EndChat`, `Rate` and `SaveImage` pass no customer identity at all.

## Shared-layer classes confirmed bridged here (2026-08-03 shared-layer pass)
Located while documenting `Shared/TalabatkLogic/TalabatkModels/` — confirmed these belong to the chat
system already bridged above, not re-documented as new entities:
- `CustomerAdminChat` — a rich chatbot/agent session state machine (bot phase, FAQ mode, escalation
  reasons, order-status "expedite" flow, rating). `CustomerAdminChat.cs`.
- `CustomerAdminChatMessage` — one message in that session, with FAQ/bot-menu action metadata.
- `ChatSetting` — the (apparently singleton) configuration row for the whole bot/chat behavior:
  session timeout, FAQ round limits, expedite-attempt cooldowns/limits, agent-escalation toggles per
  bot type. `ChatSetting.cs` — has a `CreateDefault()` alongside the fully-parameterized `Create(...)`,
  and its own `Update(...)` (note: `Update` has 4 fewer parameters than `Create` — it does not accept
  `clearHistoryOnResume`, meaning that field can be set at creation but not changed via the normal
  update path; not confirmed whether that's intentional).
- Also present but not opened: `DeliveryManAdminChat`/`DeliveryManAdminChatMessage`,
  `CustomerDeliveryChat`/`CustomerDeliveryChatMessage` — presumably parallel chat channels
  (delivery-man↔admin, customer↔delivery-man) mirroring this same shape. Flagged for whoever next
  extends the chat bridge.
- `FAQItem` — the FAQ content the bot's FAQ mode surfaces (`CustomerAdminChat.IsFaqMode`/`FaqItemId`
  above). A solidly-validated simple CMS entity (`Instance`/`Update` both require all four
  question/answer fields non-blank, trimmed) — `Shared/TalabatkLogic/TalabatkModels/FAQItem.cs`. Not
  given its own note since it's low rule-density outside what's already captured here.
